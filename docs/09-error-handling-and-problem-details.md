# Pattern 09: Error Handling & RFC 7807 / RFC 9457 Problem Details

## 1. Executive Summary & Specification Standards

**RFC 7807 (Problem Details for HTTP APIs)** and its updated successor **RFC 9457** define a standardized JSON representation (`Content-Type: application/problem+json`) for conveying human-readable and machine-parsable error details across HTTP APIs.

Before RFC 7807, APIs returned arbitrary ad-hoc error shapes:
- `{"error": "not found"}`
- `{"errors": [{"msg": "bad request"}]}`
- `{"success": false, "message": "unauthorized"}`

This lack of consistency broke client SDK auto-generation and cross-service error propagation.

---

## 2. The RFC 7807 Data Model

```json
{
  "type": "https://api.example.com/errors/unprocessable-entity",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "Your order request contains 2 validation errors.",
  "instance": "/orders",
  "requestId": "req_8f1c4e92a01b",
  "errors": [
    { "field": "amount", "code": "MUST_BE_POSITIVE" },
    { "field": "currency", "code": "REQUIRED" }
  ]
}
```

### Standard Fields Specification

| Field | Type | Description | RFC Requirement |
|---|---|---|---|
| **`type`** | URI | A URI reference that identifies the specific problem type (e.g. `https://api.example.com/errors/rate-limited`). When dereferenced, it should provide human-readable documentation. | Required (Defaults to `about:blank`) |
| **`title`** | String | A short, human-readable summary of the problem type (e.g. `Bad Request`, `Not Found`). Should not change from occurrence to occurrence. | Required |
| **`status`** | Integer | The HTTP status code generated by the origin server for this occurrence of the problem. **Must match the actual HTTP response code.** | Required |
| **`detail`** | String | A human-readable explanation specific to this occurrence of the problem. | Optional |
| **`instance`** | URI | A URI reference that identifies the specific resource or endpoint where the problem occurred (e.g. `/orders/ord_123`). | Optional |
| **`requestId`** | String | Extension field: Distributed correlation ID for tracing the failed request in centralized logs (Datadog, Loki, Jaeger). | Best Practice |
| **`errors`** | Array | Extension field: Array of granular field-level validation errors. | Best Practice |

## 3. Comprehensive HTTP Error Status Code Mappings

| Code | Standard Title | When to Use |
|---|---|---|
| **`400`** | Bad Request | Syntactic parsing failure (e.g. malformed JSON body, invalid query parameter format). |
| **`401`** | Unauthorized | Missing, invalid, or expired authentication credentials. **Must include `WWW-Authenticate` header.** |
| **`403`** | Forbidden | Authenticated user lacks permission / roles to access resource. |
| **`404`** | Not Found | Target URI does not exist or target resource cannot be found. |
| **`406`** | Not Acceptable | Server cannot generate response matching client's `Accept` header. |
| **`409`** | Conflict | State conflict (e.g. concurrent in-flight idempotent request, duplicate email unique constraint). |
| **`412`** | Precondition Failed | Conditional request precondition (`If-Match`) failed (Optimistic Concurrency Control). |
| **`413`** | Payload Too Large | Request body exceeds maximum allowed size (`MaxBytesReader`). |
| **`415`** | Unsupported Media Type | Request payload `Content-Type` is unsupported by this endpoint. |
| **`422`** | Unprocessable Entity | Syntactically valid JSON, but semantic/business rule validation failed (negative amount, missing required field). |
| **`429`** | Too Many Requests | Rate limit exceeded. **Must include `Retry-After` header.** |
| **`500`** | Internal Server Error | Unexpected server bug or uncaught panic. |
| **`503`** | Service Unavailable | Downstream dependency outage or open Circuit Breaker. |

## 4. Security Invariant: Never Leak Internal Details

```
❌ BAD (Security vulnerability):
{
  "status": 500,
  "detail": "pq: relation 'users' does not exist at /src/internal/db/postgres.go:42 (pgx connection failed: dial tcp 10.0.1.24:5432)"
}

✔ GOOD (Secure & Production-Ready):
{
  "type": "https://api.example.com/errors/internal",
  "title": "Internal Server Error",
  "status": 500,
  "detail": "An unexpected error occurred. Please contact support quoting requestId req_8f1c4e92a01b.",
  "requestId": "req_8f1c4e92a01b"
}
```

**Rule:** Log full stack traces and raw error messages internally via structured logging (`slog.Error`), but return generic, sanitized Problem Details to external clients.
